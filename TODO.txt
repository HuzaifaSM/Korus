MYTHIC AFFIX REWORK:
  - mythic affixes are currently just reskinned numeric affixes (MythicAffix subclasses Affix, same minVal/maxVal/isPercent model, aggregated the same generic way as any other affix)
  - goal: mythic affixes should be rule-breaking/build-defining like PoE uniques, not stat sticks. soulbound affixes stay as 'same stats but bigger numbers', mythic becomes the 'mechanic-altering' tier
  - plan:
    > new effect registry (scripts/mythicEffects.py): one class/function per unique mythic mechanic, implementing whichever combat hook it needs (onBeforeDamage, onPrepareHit, onAfterMitigation, getEffectiveArmour, etc. - same hook system used by class ascendancies)
      - JSON keeps bookkeeping (id, name, description, slot, level req, weight), new "effect" field names which registered implementation to use
      - mirrors existing abilities.py pattern of separating data-driven effect params from the code that applies them
    > item-level hook composition: give equipped items a way to register into the same hook points ascendancies use (e.g. self._mythicEffects list on Entity, consulted by base hook implementations alongside the class override) so item effects and class mechanics compose without fighting each other
    > ability-granting mythic/soulbound affixes: inject the granted Ability into self._abilities on equip, remove on unequip - reuses the existing ability system entirely
    > guardrail against 'equip for the buff, then discard' abuse: any 'permanent gain' effect must track accumulated state on the ITEM, not the player, so unequipping loses it. everything else should be live-recalculated (e.g. '+x% damage per 1% missing hp'), never a stacking buff that outlives the item
    > content: hand-design a small flagship set first (~5-10 across a few slots, including at least one ability-granting example) before mass-producing - existing 43 mythic affixes aren't salvageable, full rewrite
    > fold in the rollMythicAffix None-crash fix (equipType not in MYTHIC_AFFIX_POOL returns None, caller doesn't guard against it) as part of the content pass, since slot coverage changes anyway
  - add 'mythic' crafting runes:
    > deal specifically with mythic affixes. e.g. 'mythic growth rune' to add a mythic affix to a mythic item that doesn't have one
    > basically standard crafting runes but only useable on mythic items
